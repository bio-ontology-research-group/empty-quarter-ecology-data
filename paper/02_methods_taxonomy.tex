\subsection{Taxonomy normalization and mapping}
\label{methods:taxonomy}

Amplicon classifications were assigned against SILVA 138.2. We retain
the original classifier lineage and ASV identifier as the primary
evidence. The combined Trips~1--5 export contains two source
encodings: the seven SILVA rank fields alone, or those seven fields
followed by a separate species-assignment field and a numeric
confidence. QIIME artifact provenance identifies the latter as an
appended species assignment rather than an eighth rank. We therefore
normalize only the ordered domain--species fields: rank prefixes are
removed, empty and unclassified values are represented explicitly, and
the separate species assignment is retained in a provenance ledger but
never promoted into the asserted lineage.

A fail-closed normalization step evaluates the historical
SILVA-to-NCBI candidates against a pinned NCBI Taxonomy release (the
OBO Foundry NCBITaxon release \texttt{2025-03-13}, built from the NCBI
organismal taxonomy of 2025-03-01). An NCBI identifier is retained
only when it resolves, has a compatible rank and label or documented
synonym, and its ancestor chain is compatible with all retained
higher-rank identifiers in that source lineage. A missing, ambiguous
or incompatible candidate is replaced by a deterministic project class
scoped to the complete truncated source lineage and rank, rather than
by the nearest ancestor's identifier, which would conflate a named
child with its broader ancestor. Each decision records the source
lineage and rank, candidate identifier, validation outcome, final
identifier and reason. The output mapping must cover every canonical
lineage represented in both the Trips~1--5 taxonomy export and the
feature table; otherwise generation stops.

Existing project identifiers are retained only when all explicit
historical uses share one normalized rank, label and nearest explicit
parent context; a reused identifier that acquires more than one
corrected context is replaced in every affected use by contextual
classes. Conflicting historical evidence is therefore contextualized
rather than resolved according to file order. The mapping builder emits
corrected mappings, a decision ledger, a clean project taxonomy module
and a manifest containing input and output checksums, and the
abundance-ABox generator accepts only a passing, checksum-matched
manifest.

We evaluated cross-resource alignment to GTDB \cite{gtdb} and
iNaturalist separately from this SILVA-to-NCBI layer, in an earlier
exploration whose candidate tables are not part of the release. The
conclusion that exploration supports is a negative one: homonyms,
\emph{Candidatus} names, placeholder taxa, GTDB split taxa, rank
conflicts and database-version drift can all produce identical labels
for non-identical concepts, so label agreement alone does not
establish extensional identity. The canonical release modules
therefore contain no \texttt{owl:equivalentClass} assertions generated
from those lexical candidates. Unreviewed GTDB and iNaturalist
candidates are excluded from the asserted crosswalk, and we claim no
mapping precision or recall because a stratified manual gold standard
has not been completed. This conservative representation permits
queries over the original SILVA lineage and validated NCBI classes
without turning lexical similarity, a shared label or a supplementary
species call into unsupported taxonomic identity.
