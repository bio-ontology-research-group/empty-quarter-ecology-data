\subsection{Taxonomy normalization and mapping}\label{methods:taxonomy}

Amplicon classifications were assigned against SILVA 138.2. We retain
the original classifier lineage and ASV identifier as the primary
evidence. The combined Trips~1--5 export contains two source encodings:
the seven SILVA rank fields alone, or those seven fields followed by a
separate species-assignment field and a numeric confidence. QIIME
artifact provenance identifies the latter as an appended species
assignment rather than an eighth rank. We therefore normalize only the
ordered domain--species fields. Rank prefixes are removed, empty and
unclassified values are represented explicitly, and the separate
species assignment is retained in a provenance ledger but is never
promoted into the asserted lineage. This rule also preserves, without
silently adjudicating, supplementary species calls that conflict with
the classifier's species field.

A fail-closed normalization step evaluates the historical
SILVA-to-NCBI candidates against a pinned NCBI Taxonomy release: the OBO
Foundry NCBITaxon release \texttt{2025-03-13}
(\path{http://purl.obolibrary.org/obo/ncbitaxon/2025-03-13/ncbitaxon.owl}),
which is built from NCBI organismal taxonomy version 2025-03-01. The
exact artifact consumed is 1,646,833,334 bytes with SHA-256
\texttt{5238897945e50ceb9007a1f96f40d1e8774456c3a0d691292fe7e8e9b5b1287d};
the checksum identifies the file and the release identifier states which
version it is. The source ontology IRI, version IRI,
\texttt{owl:versionInfo}, NCBI source date, source checksum and derived-subset
checksum are bound machine-readably in
\path{ontology/ncbitaxon_release_identity.json}; the historical retrieval
date was not recorded and remains an explicit null. An NCBI
identifier is retained only when it resolves, has a compatible rank and
label or documented synonym, and its ancestor chain is compatible with
all retained higher-rank identifiers in that source lineage. A missing,
ambiguous or incompatible candidate is replaced by a deterministic
project class scoped to the complete truncated source lineage and rank.
It is not replaced by the nearest ancestor's identifier: doing so would
conflate a named child with its broader ancestor. Each decision records
the source lineage and rank, candidate identifier, validation outcome,
final identifier and reason. The output mapping must cover every
canonical lineage represented in both the Trips~1--5 taxonomy export and
feature table; otherwise generation stops.

Existing project identifiers are retained only when all explicit
historical uses share one normalized rank, label and nearest explicit
parent context. The audit is repeated against the corrected parent IRIs
to a fixed point; a reused identifier that acquires more than one
corrected context is replaced in every affected use by contextual
classes. Finally, every occurrence of the same rank-truncated source
lineage must have one final IRI, label and mapping status regardless of
which lower-rank descendants occur beneath it. Conflicting historical
evidence is therefore contextualized rather than resolved according to
file order.

The mapping builder emits corrected JSON and tabular mappings, a
decision ledger, a clean project taxonomy module, an audit report and a
manifest containing input and output byte counts and SHA-256 checksums.
The abundance-ABox generator accepts only a passing, checksum-matched
manifest. It aggregates independently by profile, rank, final
identifier and truncated source lineage, thereby preserving distinct
classifier contexts even when they share an accepted NCBI identifier.
No global label or parent is inferred by overwriting one source
lineage with another.

Cross-resource alignment to GTDB \cite{gtdb} and iNaturalist was
evaluated separately from this SILVA-to-NCBI layer, in an earlier
exploration whose candidate and discordance tables are not part of the
release and were not regenerated for it; the counts they reported are
therefore not restated here. The conclusion that the exploration
supports is a negative one and does not depend on those counts.
Homonyms,
\emph{Candidatus} names, placeholder taxa, GTDB split taxa, rank
conflicts and database-version drift can all produce identical labels
for non-identical concepts. Label agreement and the former
parent-voting heuristic therefore do not establish extensional
identity.

The canonical release modules contain no
\texttt{owl:equivalentClass} assertions generated from those lexical
candidates. Unreviewed GTDB and iNaturalist candidates are excluded
from the asserted crosswalk, and no mapping precision or recall is
claimed because a stratified manual gold standard has not been
completed. This conservative representation permits queries over the
original SILVA lineage and validated NCBI classes without turning
lexical similarity, a shared label or a supplementary species call into
unsupported taxonomic identity.
