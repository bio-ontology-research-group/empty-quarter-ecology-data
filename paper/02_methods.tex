At each site, we collected samples from three distinct soil
compartments: bulk surface soil (0 cm depth), bulk subsurface soil
(5--10 cm depth, hereafter ``deep''), and subsurface soil collected
near roots (5--10 cm depth, hereafter ``root-adjacent''). 
%The legacy label ``deep'' and the class label ``Deep Soil Sample'' denote the 5--10~cm bulk compartment and do not imply a greater sampling depth.
We obtained three co-located field replicates per compartment by
placing soil into sterile tubes, either by scooping soil directly into
the tube or using sterile plastic spoons; these replicates are not
independent sites. We preserved samples at $-20$\degree C in the field
using an Engel MR040F portable freezer. At the end of each expedition,
we transferred samples to an $-80$\degree C freezer in the laboratory.

We included positive and negative controls for each sampling campaign
to mitigate and control for contamination artifacts. The
positive control design differed by expedition. Trips~1 and 2 used the
ZymoBIOMICS HMW DNA Standard D6322, supplied as purified
high-molecular-weight DNA, which we extracted along with the samples after the trip.
Trip~3 used the whole-cell ZymoBIOMICS Microbial Community Standard
D6300, which we also later extracted. Trip~4 had no positive
control. Trip~5 used D6300, but its positive and negative control pair
were sequenced by shotgun metagenomics rather than by the 16S assay.
D6322 contains seven bacterial genomes at 14\,\% genomic DNA each and
\emph{Saccharomyces cerevisiae} at 2\,\%; D6300 contains eight
bacterial genomes at 12\,\% each and two yeasts at 2\,\% each. These
manufacturer genomic-DNA fractions are composition specifications, not
expected 16S read fractions.

Negative controls included distinct extraction blanks and PCR blanks.
One extraction blank was included per extraction day, and an
extraction day could contain samples from several expeditions, so an
extraction blank is linked to its extraction batch and %never 
not directly to a trip. Trip~4 records five numbered blanks and one
unnumbered blank, but the blank covering a three-day extraction was
not sequenced, leaving all or part of 23 sites without a sequenced
blank. Author-confirmed controls are recorded in a ground-truth
table; identity, batch-membership and assay-applicability claims that
await laboratory confirmation are represented in the graph as
evidence-bearing dispositions rather than as ground truth, and no
field-blank instance is asserted because no sterile-bag inventory was
recovered.

\subsection{DNA extraction and sequencing}

We utilized 0.9--1.2 g of soil for DNA extraction using the PowerLyzer
PowerSoil Kit (QIAGEN, catalog \#12855-50) or the DNeasy PowerSoil Pro
Kit (QIAGEN, catalog \#47014). We homogenized all samples with the
PowerLyzer 24 Homogenizer and completed extraction either manually or
via the automated QIACube Connect system. We quantified the eluted DNA
using the Qubit HS dsDNA kit.

We amplified bacterial DNA using the Bakt\_341F
(\texttt{CCTACGGGNGGCWGCAG}) and Bakt\_785R
(\texttt{GACTACHVGGGTATCTAATCC}) primer pair
\cite{klindworth2013primers} to target the V3--V4 region of the 16S
rRNA gene. Both primers carried Illumina overhang adapter sequences.
We performed amplification using the Multiplex PCR kit
(QIAGEN, catalog 206143) with an initial activation at
95\,\textdegree C for 15\,min, 35 cycles of 94\,\textdegree C for
30\,s, 57\,\textdegree C for 90\,s and 72\,\textdegree C for 90\,s,
and a final extension at 72\,\textdegree C for 10\,min, and sequenced
the resulting pools on an Illumina NovaSeq~6000 platform.
We processed all samples in the PI's laboratory at KAUST.

\subsection{Archived-soil pH acquisition and admission}\label{methods:ph}

We measured archived dry soil after sieving below 2~mm. Each assay used an independent 1~g scoop suspended in 2.5~mL 0.01~M CaCl$_2$. Electrodes were calibrated at two points (pH 7 and 10), and we recorded the electrode slope and pH-10 buffer read-back for every session. A measurement was admitted only if its session was calibrated, the electrode slope was between 95\% and 102\%, and the read-back was within 0.1 pH units of nominal.

\subsection{Schema validation}

To ensure structural integrity within the RDF graph, we used Shape
Expressions (ShEx) \cite{shex}. ShEx provides a formal structural
schema language that validates the presence, cardinality, and datatype
of RDF properties. We defined specific ShEx shapes for all core entity
types in the knowledge graph. These entity types include sampling
sites, soil samples, DNA extracts, sequencing datasets, measurements,
quality control records, laboratory control materials, control roles,
laboratory batches, control sequence occurrences, archived-soil pH
processes, values and sessions, and taxonomy mappings.

We integrated this schema validation into our deployment workflow
using a Shape Map. The Shape Map functions as a binding directive,
explicitly linking node selectors (e.g., all instances of the sampling
site class) to their respective ShEx shape definitions. The workflow
tests each newly generated segment of instance data against the
schema. It terminates the deployment if it detects missing mandatory
properties (e.g., GPS coordinates for a sampling site) or invalid
datatypes. This constraint application guarantees that all generated
data conforms to the expected structural properties.
We implemented this validation using the Apache Jena ShEx library (v4.10.0) invoked from custom Groovy scripts.
The multi-gigabyte taxonomy ABox is excluded from this memory-bounded
ShEx run; the exact generated file is instead parsed in full with an
independent Turtle parser and checked by a streaming validator over
every classification process--dataset--quality--value relationship.

\subsection{Logical consistency (OWL reasoning)}

We checked logical consistency using the ELK reasoner \cite{elk}. The
ELK reasoner operates on the OWL 2 EL profile and detects
unsatisfiable classes and contradictory axioms within ontologies. ELK
implements a polynomial-time algorithm, facilitating the consistency
validation of large knowledge bases. However, this performance benefit
necessitates a tradeoff in logical expressivity, as the OWL 2 EL
profile does not support complex constraints such as universal
quantification or inverse object properties found in ontologies like
the Semanticscience Integrated Ontology (SIO). We employed ELK instead
of more expressive reasoners (e.g., HermiT \cite{hermit}) because
verifying the large knowledge graph we created with a more expressive
reasoner proved impossible due to computational complexity. The
current run is memory-bounded and excludes the multi-gigabyte taxonomy
ABox and large reference modules, so a successful run establishes
bounded consistency of the included modules rather than whole-graph
OWL 2 DL consistency. This approach enabled rapid continuous
integration during ontology development.

\subsection{Reproducible workflow}

Release generation, validation and manuscript-derived statistics are
orchestrated from one Nextflow entry point (\texttt{main.nf}), with
separate local and cluster profiles that change execution
infrastructure without changing process definitions. The workflow
regenerates the site, environmental-measurement, sample, XRF, DNA,
sequence-record, quality-control, laboratory-control and pH modules
from their declared sources and requires every byte stream to match
the staged release candidate, so the deposited modules and the
manuscript statistics are produced from the same auditable run.
